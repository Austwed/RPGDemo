# 状态转换与事务顺序

用于说明当前工程怎样落实业务规则。

## 通用修改入口

探索事务由 BaseSceneController.Change 捕获同伴状态，复制 BaseState，在副本上执行修改，再处理序章装备与岗位资格。BaseSaveStore.Save 对拟提交状态执行全量校验，通过后保存会话并替换当前 State。异常时保留原 State，界面显示失败原因。

会话由 BasePlaySession 的内存存储承接，磁盘自动档在 ProgressChanged 的指定节点触发。普通操作不会逐次写磁盘。

界面预估沿用已载入状态或调工草案计算产量。实际日结仍重新检验当时的状态并提交。兵营的九项范围先逐组核对驻守、威胁和进攻的顺序，再一次写入草案。探索每帧先取得移动与交互结果，再更新附近目标、名牌和箭头。

## 备战到战斗

BaseBattlePreparation 保存人员快照、地图键、候选、敌阵、所选军需与位置。打开或编辑草案不提交正式状态。

确认使用 Problem(state,true) 再校验，通过 Roster 只取得所选且已落位者。未到达的人员不进入远征战场。CaptureTroops 冻结每名普通兵的血量和作战属性，ReservePrepared 建立整场单档配额，BattleScenePlacement.Start 应用落点，战斗状态进入正式进行中。

会话观察到由非战斗变成战斗时，将修改前的探索状态写战前自动槽，再接受新的战斗状态。重载读取此档回到确认前的地点，重新准备部署草案。

## 军需与战果

军需配额先准备，再进入 fighting。总库存保留，Available 按库存减全部配额计算。FullConsumptionGrade 为 1 或 2 的正式配额在 Finish 中全额扣该级数量。扣量须对应所有实际参战普通兵，结算后解除队伍战斗状态、移除配额、登记 FinishedIds。

旧实验配额存在按安全和损失人数累计磨损的路径，正式单档配额走全额扣除分支。不能把旧分支的磨损率写成新版正式军需规则。

战报、俘虏、奖励和剧情各使用同一场次身份。不同路线调用自身 Complete，再写回探索地点与进度。失败须保留原事务，已完成的场次不得重复。

## 奖励

BaseBattleLoot.Create 或 AppendRewards 先建立唯一清单并固定随机品质，Demo 路径立即 Deliver。逐个尝试可访问的随行背包，余下的掉落保留待领。主动领取整份奖励时先试放全部物品，通过后才扣款、记领取或推进对话。已发物品标记去向，ConsumeReceipt 只消费显示收据。

手动古窟战取胜后，任一受玩家操控的队长从洞口撤离才返回探索。古窟首通记录胜绩、证据和等待处置的迦兰。窝点首通立即免费领奖；重复领奖通过 ClaimProblem 后写本场奖励结算标记、扣体力、发放奖励并清空待领奖。

## 切图与存档

非战斗地图实际切换并写入落点后，ProgressChanged 通过 Location、CurrentMapId 或序章村庄身份变化判断进入新地图，写入自动档。战斗结算回探索同样触发。读档、打开菜单及取消部署不单独写盘。

存档编码后先反解校验，写同卷临时文件，再替换正式文件并保留备份。新局在姓名确认前只保留会话，确认后写第一个自动档。

第 19 版存档支持原有带缩进的 JSON 和新写入的紧凑 JSON。同一会话中，读档页按文件内容复用已校验的槽位摘要，手动保存页只列三个手动槽。正常槽用「读取」校验并恢复主档。主档损坏时再校验上一版备份，通过校验且可游玩才显示「恢复上次存档」。该操作载入备份，不覆盖磁盘。长椅坐稳事件写入轮换自动槽，坐下和起身的动画不改变存档中的探索站位。

## 重复与中断

| 事务 | 防重身份或状态 | 失败结果 |
| --- | --- | --- |
| 备战提交 | 活跃战斗与草案快照 | 保留草案并报原因 |
| 军需结算 | 配额阶段与 FinishedIds | 拒绝重复扣除 |
| 战役战果 | 战斗标识与 SettledIds | 已结算场次保持原值 |
| 自动奖励 | 清单行状态与事件标记 | 不生成第二份物品 |
| 副本领奖 | 场次加奖励后缀 | 不再扣体力 |
| NPC 一次性剧情 | 对应剧情标记 | 重谈进入后续分支 |

## 实现位置

当前对应 BaseBattlePreparation、BaseSupply、BaseBattleLoot、BaseRuinsRewards、BaseSaveCatalog、BaseSaveStore 和各路线控制器。正式业务定义分别引用系统卷，调用顺序变更须同时核对对应验收用例。
