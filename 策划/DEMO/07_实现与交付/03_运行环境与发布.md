# 运行环境与发布

## 工程

Unity 版本 6000.6.4f1。发行场景顺序为 Demo_Launcher、Base_Stage2。父目录策划仓与 RPGDemo 工程是独立仓库，交付以明确工程版本、内容快照和构建报告对应，不把父仓提交当成 APK 版本。

## 平台

游戏显示名暂用 DEMO，Windows 窗口、Android 应用名及游戏标题采用相同代号。发行图标使用序章短剑。Windows 继续读取原数据目录，Android 沿用原安装标识。

Windows 键鼠与 Android 横屏共用正式规则、地图和布局。Android 最低 API 26、目标 API 36，允许左右横屏，不允许竖屏。工程 Android scriptingBackend=1，发布以 IL2CPP 配置构建；实际 ABI、压缩和输出文件由当次构建记录核对。

UI 以安全区内 16∶9 游戏框运行，固定逻辑尺寸 1280×720；小屏验收包含 854×480 和 960×432。安卓当前探索输入使用左侧摇杆与右侧交互按钮，战场采用点格、长按与拖动。

## 安卓构建

使用工程 `AgentScripts/Build-AndroidDemo.ps1`，默认输出 Builds/Android/DEMO.apk，可另给路径。脚本复制 Assets、Packages、ProjectSettings 到英文临时目录构建，默认排除 DemoStages、StoryScene 自定义测试包、性能测试运行数据和四张已有替代的旧地表图。发行复制中移除 AI assistant／inference 包，原工程不因此被删除或改写。

BuildAndroidDemo 使用启用场景、LZ4HC 与详细构建报告。成功输出 APK、unity.log 和 assets.tsv；资产表按打包字节聚合，检查体积时同时看压缩包和打包资产。Development 与 IncludeDevelopmentAssets 是显式选择，不作为发行默认。

## 随包开发模板

随包场景清单收录 35 号配表驱动验证模板，开发场景默认推荐该项。桌面开发入口按实际目录枚举文件，安卓无法直接枚举 APK 内目录时读取同一份清单。两个入口使用同一模板内容。独立地图 JSON 仍由地图编辑菜单导入。

## 体积与内容

每次发布记录APK实际字节、摘要及构建资源表。包内内容以当次构建报告核对，不用工作区总大小推断。

发布排除 Library、Temp、Logs、用户存档、策划原文、网页原型、图片生成中间件、开发测试档和本机凭据。Resources 会打入可加载资源，保留的回退图、旧角色图或测试模板须逐项检查引用与包报告再裁剪，不能靠文件名批量删素材。

## 启动和存档

入口先加载随包数值及正文，再进入最近兼容档；没有可用档从序章选角命名。当前存档版本 19，首个自动档在姓名确认后建立；正式与自定义地图测试档分开。退出会话不另写档。发行文本本机副本根据键 revision 更新变化的新版正文，保留其他已存在键的本机改稿。

## Windows 转场性能检查

开发构建保留 `DemoStages` 阶段档，用 `-slgTransitionPerf` 启动。将 `BASE_CONQUEST_UI_CHECK_SAVES` 指向已创建的空目录，`SLG_TRANSITION_PERF_RESULT` 指向报告文件的绝对路径。前后版本使用相同分辨率和图形设置，每次运行分配一个新存档目录。

检查填满六个自动槽和三个手动槽，往返灰岩营地、灰岩镇及沉眠古窟入口，再读取手动主档，并在隔离存档中损坏主档后从同槽备份恢复。报告分列操作回调结束、目标地图就绪、第一帧可见画面、键盘操作得到响应的耗时，以及建图和棋盘刷新的次数。单独测量状态事务或棋盘时，在报告中标明计时边界和使用的资源。

同一开发包可用 `-slgScenePerf` 样测探索、仓库数量调整及一倍速和三倍速守营。使用新的隔离存档目录，以 `SLG_SCENE_PERF_RESULT` 指定报告文件，并将 `SLG_PERF_VILLAGE_FIXTURE` 指向主线回归 `VerifyDemoPlayerRoute` 生成的 `drill.json` 的绝对路径。原始帧样本与汇总保存在同一报告目录。

## 数值发布

在 Unity 选择「SLG → 其他工具 → 导入 → 导入策划表」，打开已保存的工作簿，核对当前快照与待写结果的差异，再确认更新运行快照及四份阶段档。发布用系统数值配置表完整导入，试玩调参表的认可改动需先写回总表。已有存档仍读取自身的数值快照。个人试玩从本次重新生成的调参备战档开始。[导入与回写](../05_数值与配置/01_字段字典与配表说明.md#导入与回写)

## 交付核对

新增 Unity 脚本随 `.meta` 交付，GUID 使用唯一的 32 位十六进制值。核对 Unity 导入后的编译清单是否包含新增脚本。

核对工程版本、工作簿与运行包、文本键、地图包、场景布局、资源键及构建报告。存档沿用自己的配置快照，复现时不能混用不同版本。验收记录前置、操作、实际结果和证据，结构、画面、输入与路线分别记录。

规则改动按根目录的维护顺序联动；实现未完成的目标见[设计实现差异](设计实现差异.md)。正式发布保留构建和运行所需内容，策划、原型及创作源作本地版本管理。

## Unity 6.6 诊断工具

性能探针在编辑器和开发构建内由既有命令行参数启动。场景探针和专用存档路径在播放器内限 Windows 开发构建。对象查找和程序集枚举使用 Unity 6.6 API。
