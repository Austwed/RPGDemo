# 模块与数据结构

## 运行结构

`Demo_Launcher` 负责正式入口，`Base_Stage2` 承接探索、设施、对白和共用布局。`BaseSceneController` 协调会话、地图、人物、事务和界面；实时战斗由 BattleSceneController／RealtimeCampaignBattle 及各战斗模型承接，正式部署复用战场，不建立一套独立演示棋盘。

| 模块 | 核心数据 | 对外行为 |
| --- | --- | --- |
| 会话与存档 | BasePlaySession、BaseState、BaseSaveCatalog、BaseSaveStore | 建立／复制会话、磁盘槽、读档与战前快照 |
| 人员和岗位 | BaseLeader、BaseWorkerBucket、BaseDevelopment、BaseMusterState | 资格、岗位、负责人、编队与补位 |
| 物品 | BasePersonalEquipmentState、BasePartyInventory、Backpack | 实例身份、槽位、装备和仓库事务 |
| 经营 | BaseEconomyRules、BaseDayReport、WorkshopProgress | 预估、生产、恢复、日期和口粮 |
| 备战与军需 | BaseBattlePreparation、BaseSupplyState | 草案、落点、实际参战名单和单档配额 |
| 战斗 | BaseCampaignSession、BattleSoldier、RpgRules | 实时位置、命令、攻击包、AI、时钟和结局 |
| 战果与奖励 | BaseAftermath、BaseBattleLoot、BaseRuinsRewards | 伤亡、俘虏、一次性发放与体力领奖 |
| 主线与任务 | BaseDemoProgress、Intro、Defense、Finale、Flow、Quests | 条件、证据、目标、对话和阶段变化 |
| 地图与道路 | BaseStoryScenePackage、ReleaseMaps、Campaign、Adventure | 七图布局、行军、地图记忆和实际地点 |
| 文本与视图 | StoryTextDocument、UiPrefabBinding、场景布局源 | 正文替换、变量、控件数据与事件绑定 |

## 状态根

BaseState 保存 Day、FoodPaidDay、LastCompletedDay、PlayerLeaderId、PlayerX/Y、Inventory、Rules、Leaders、Workers、Muster、Development、Supply、Campaign、Aftermath、Town、Backpack、Construction、Layout、Caravan、Quests、Adventure、PersonalEquipment、Demo、Achievements、受伤对白日和 NPC 集合、同图战斗 ID、日报。

BaseLeader 有稳定 Id、Name、外观、职业和 RPG 数据、生命／上限、岗位、目标岗位、岗位锁定、队伍、外出、训练、装备及地图落点。普通兵按同类桶存储 Count、职业、生命、岗位、队伍、来源及成员编号 SoldierNumbers。BaseState.LastSoldierNumber 记录发出的最大编号。拆分、调岗和战斗回写保留各自编号；征募新兵继续递增。旧档按原有名册顺序补号。BasePersonnel.Soldiers 提供士兵行，PersonnelRosterRow 统一显示，设施和备战分别绑定操作。

BaseDemoProgress 保存主线 Stage、接取／交付／救援日期、剧情证据、候选同伴、首防、攻寨、奖励、地图包、地形记忆、配置来源摘要、一次性 Flow 和序章教学。存档兼容版本 19，与 DemoProgress.Version=1、数值包 Version=1、创作包版本分开。

## 跨模块接口

显示层读取状态并发出有明确参数的请求；业务层在状态副本上修改，验证成功后替换会话。显示文本不会决定任务是否完成，按钮位置不会决定物品归属。开战、发奖、日结、切图各有唯一提交入口，防重标记与数据一并持久化。

数据复现入口分别为本区上级地图底稿、运行数值、文本目录和布局快照。类的组织可以调整，业务行为、事务顺序和数据单位保持一致。遗留 BaseInnState 字段仍在根结构中，但正式旅店业务已退役，字段存在不代表玩家仍能住宿。
