# Demo 策划目录

作品集现行版为七页系统总表与单页试玩表，试玩表分四个主题、八个配置区。[系统总表与字段查询](https://austwed.github.io/portfolio/read/system-table/index.html) · [试玩调参表与原件下载](https://austwed.github.io/portfolio/read/trial-table/index.html)。本仓库随此版工程保留的是较早的 20＋4 页签工作簿。

面试阅读分两份独立单篇：[重点策划案](00_总策划案.md)说明身份、目标、完整体验及十三项代表设计；[游戏设计规格书](https://austwed.github.io/portfolio/read/design/)按产品、系统、数值、关卡、界面、内容、数据、制作及验收组织详细规格。八卷继续作为模块维护区。设计与实现有差异时查[设计实现差异](07_实现与交付/设计实现差异.md)。

## 数值与数据

[系统数值配置表](基地征服-系统数值配置表.xlsx)维护完整规则，[试玩调参表](基地征服-试玩调参表.xlsx)提供此快照的四页常用数值。字段归属和导入操作见[配表说明](05_数值与配置/01_字段字典与配表说明.md)。卷内保留运行参数、文本、地图、布局和资源数据的当前快照，用于核对版本与复现实际内容。工作簿、运行包和存档的不同版本分别标明。

## 维护与状态

具体参数在正式工作簿维护，公式和取整在数值卷维护；规则在所属卷定义，其他卷引用。设计意图归项目制作理念，当前待办与历史分别归STATUS、JOURNAL和handoff。已定待实现项保留完整目标，并在实现卷记录当前差异。

交易、日结、部署、战果、切图和存读档需说明前置、数据、提交顺序、结果、失败／取消、重复／中断、场景例外和验收样例。普通交互写入口、行为和结果；显示项写数据来源、显隐及样式。

修改沿系统、配置、流程、界面／文本、实现和用例联动，编队→部署→开战→军需→战果是同一提交链。地图、布局和资源保留可核对的精确数据；代码组织可以调整，业务行为和数据单位一致。

旧编号从策划索引转接现行文件，不再维护旧五案或旧回稿。历史材料和整理记录保存在项目归档目录。

## 术语表

| 术语 | 定义与单位 |
| --- | --- |
| 队长／普通兵 | 人物单位与可生产、可参战兵员；职业另分剑、弓、骑 |
| 编队位次 A/B/C | 至多三名队长的顺序及独立策略和范围 |
| 随行／出征／在岗 | 可访问队伍、世界行军队伍、设施岗位，三个状态分开 |
| 备战草案 | 尚未提交的候选、人数、军需与落点 |
| 实际参战 | 最终落位且开战提交的名单，决定本场消耗和战损 |
| 军需一级／二级 | 每普通兵一份，整场单档；队长不占份数 |
| 地格／细格 | 每地格细分2×2细格，距离按字段单位换算 |
| 游戏日／战斗时间 | 休息与行军推进整数日；战斗推进连续秒 |
| 物品模板／实例 | 物品定义与有唯一身份、品质、归属的具体物品 |
| 战果／副本领奖 | 本场伤亡与掉落处理／首通或支付体力领取副本额外奖 |
| 快照／编辑源 | 核对时导出的版本数据／持续维护的原始文件 |
| 已定待实现 | 设计明确，当前代码或运行包尚未落实 |
